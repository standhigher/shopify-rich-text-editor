# 1.0.0 Verification Record

Status: release candidate verification prepared; npm publication is intentionally
not performed on the implementation branch.

## Local gates

Run from the repository root:

```bash
pnpm release:check
```

This runs `git diff --check`, workspace typecheck, package and compatibility
tests, production build, npm pack dry-runs, package artifact allowlist checks,
and clean consumer imports for Core root, Core experimental, Editor root,
Editor experimental, Editor CSS, and Server root.

Build the online component showcase separately:

```bash
pnpm build-storybook
```

The performance suite records repeatable processing measurements for 10KB,
50KB, and 100KB documents with the local Node version. CI should retain the raw
JSON lines from `pnpm performance:baseline` as evidence rather than comparing
absolute times across machines.

## Publish-candidate checks after merge

- Publish a prerelease with the `next` dist-tag.
- Install Core, Editor, and Server in a clean temporary project.
- Verify root imports, experimental imports, declaration files, editor CSS, and the minimum lifecycle.
- Inspect npm dist-tags before and after publication.
- Publish `1.0.0` to `latest` only after all package and registry checks pass.

## Rollback record

Record the last verified package versions and the intended dist-tag commands
here after the post-merge publish rehearsal. Never record npm tokens, store
identifiers, or customer data in this file.
