# 0.4.x Extension Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立不依赖 React、Polaris、Shopify SDK 的共享 Core 契约，使自定义 Node、Toolbar 和服务端 Serializer 可以被一致注册。

**Architecture:** 新增依赖无关的 `@standhigher/shopify-rich-text-core` workspace 包，集中维护 `RichTextDocument`、错误、Extension 和 Migration 契约。编辑器包负责客户端注册，服务端包负责服务端注册；0.2.x/0.3.x 的基础用法继续可用。

**Tech Stack:** TypeScript, Tiptap 3, React 18, Zod, Vitest, pnpm workspaces.

---

## 分支和前置条件

```bash
git switch main

```

开始前必须确认 `0.3.x` 已合并到 `main`，并通过 `pnpm -r typecheck`、`pnpm test`、`pnpm build`。

## Task 2：定义 Extension 和 Migration 契约

**Files:**

- Create: `packages/rich-text-core/src/extensions.ts`
- Create: `packages/rich-text-core/src/migrations.ts`
- Create: `packages/rich-text-core/tests/contracts.test.ts`
- Modify: `packages/rich-text-core/src/index.ts`

- [x] **Step 1：定义 Extension 元数据**

Extension 至少包含稳定 `id`、`version`、依赖列表和提供的 Node/Mark 名称；依赖顺序必须可确定。

- [x] **Step 2：定义客户端和服务端能力声明**

契约分别描述 Tiptap Extension、Toolbar Item、Serializer、Renderer 和 Channel 支持，避免客户端注册了服务端无法处理的 Node。

- [x] **Step 3：定义 Migration 接口**

Migration 使用 `from`、`to` 和纯函数 `migrate(document)`；同一输入重复执行必须产生相同输出，迁移函数不得修改原对象。

- [x] **Step 4：测试版本链和冲突规则**

覆盖缺失迁移、循环迁移、重复版本、Extension ID 冲突和不满足依赖的场景。

- [x] **Step 5：提交契约**

```bash
git add packages/rich-text-core/src packages/rich-text-core/tests
git commit -m "feat: define extension and migration contracts"
```

- [x] **Step 3：支持扩展 Serializer**

扩展可以提供 HTML/Plain Text 渲染能力，但最终输出仍必须经过 Channel Adapter 和 Sanitizer。

使用一个最小测试 Node 验证：客户端可初始化、服务端可校验、服务端可输出；只注册客户端而未注册服务端时必须失败。
