# 0.3.x Core Stability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把当前 0.2.x 编辑器和服务端闭环稳定为可嵌入业务表单的 MVP，并保持现有接入代码兼容。

**Architecture:** 保留现有 `JSONContent` 编辑器 API和 `RichTextDocument` 服务端信封，不在本版本强制引入新的 Core 包。先修复编辑器受控状态、Change 生命周期、上传错误和服务端基础校验，再用组件测试和边界测试固化行为。

**Tech Stack:** React 18, Tiptap 3, TypeScript, Zod, sanitize-html, Vitest, React Testing Library, pnpm.

## Task 2：修复受控内容和编辑状态

**Files:**

- Modify: `packages/rich-text-editor/src/components/RichTextEditor.tsx`
- Modify: `packages/rich-text-editor/src/types.ts`
- Test: `packages/rich-text-editor/tests/RichTextEditor.test.tsx`

- [ ] **Step 1：定义外部同步规则**

约定：初始化时使用 `value`；后续只有当外部 JSON 与编辑器当前 JSON 不一致时才执行 `setContent`；外部同步不得触发用户 `onChange`。

- [ ] **Step 2：实现外部 `value` 同步**

在组件生命周期中比较稳定序列化结果或文档哈希，避免每次父组件渲染都重置编辑器和撤销历史。

- [ ] **Step 3：补充 `disabled` 语义**

增加 `disabled?: boolean`，并使它同时影响 `editor.setEditable`、工具栏按钮和上传入口。`readOnly` 继续保留只读预览语义。

```bash

```

预期：初始化、外部替换、只读和 disabled 用例通过。

## Task 3：稳定 Change、上传和错误生命周期

**Files:**

- Modify: `packages/rich-text-editor/src/components/RichTextEditor.tsx`
- Modify: `packages/rich-text-editor/src/components/RichTextToolbar.tsx`
- Modify: `packages/rich-text-editor/src/types.ts`
- Test: `packages/rich-text-editor/tests/RichTextEditor.test.tsx`

- [ ] **Step 1：定义公共错误和错误来源**

增加最小的 `RichTextError` 结构，至少包含 `code`、`message`、`recoverable` 和可选 `cause`，并定义上传失败、编辑器初始化失败和内容同步失败的错误码。

- [ ] **Step 2：增加 `onError` 和上传状态语义**

上传回调异常时调用 `onError`，恢复按钮状态，不插入空图片节点；上传按钮在进行中禁用，文件选择完成后清空 input 以允许重复选择同一个文件。

- [ ] **Step 3：增加 Change flush 机制**

将 debounce 定时器封装为可 flush 的生命周期，组件卸载前清理定时器但不丢失已经产生的最后一次有效变更。外部同步不得调用 flush 后的用户回调。

- [ ] **Step 4：测试上传成功、上传失败和卸载前最后一次 Change**

```bash
pnpm --filter @standhigher/shopify-rich-text-editor test
```

预期：上传失败可被断言，最后一次编辑不会因为 400ms debounce 被静默丢弃。

- [ ] **Step 5：提交错误生命周期修复**

```bash
git add packages/rich-text-editor/src packages/rich-text-editor/tests
git commit -m "fix: make editor changes and upload errors observable"
```

## Task 4：收紧服务端基础校验

**Files:**

- Modify: `packages/rich-text-server/src/validation.ts`
- Modify: `packages/rich-text-server/src/types.ts`
- Create: `packages/rich-text-server/src/errors.ts`
- Modify: `packages/rich-text-server/tests/rich-text-server.test.ts`

- [ ] **Step 1：定义基础限制常量**

为文档 JSON 字节数、文本长度、递归深度、Node 数量和 attrs 数量定义可测试的默认上限，并允许服务端调用方通过配置覆盖。

- [ ] **Step 2：实现基础 Node/Mark 结构校验**

保留合法基础节点：`doc`、`paragraph`、`heading`、`text`、`bulletList`、`orderedList`、`listItem`、`blockquote`、`image` 和合法基础 Mark。未知 Node/Mark 返回结构化错误，不静默放行。

- [ ] **Step 3：实现链接和图片 URL 校验**

允许的协议与 Sanitizer 保持一致；禁止 `javascript:`、`data:` 和不带协议的远程资源。图片 attrs 至少校验 `src` 为字符串。

- [ ] **Step 4：增加恶意和边界输入测试**

覆盖未知节点、未知 Mark、超大文本、过深嵌套、危险图片 URL、危险链接 URL 和合法复杂列表。

- [ ] **Step 5：运行服务端测试**

```bash
pnpm --filter @standhigher/shopify-rich-text-server test
```

预期：基础转换和清洗测试继续通过，新增非法输入测试通过。

- [ ] **Step 6：提交服务端校验**

```bash

git commit -m "feat: enforce rich text document limits"
```
