# 0.6.x Content Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立统一的服务端内容处理管道，支持 Schema Migration、标准 HTML Import、显式 warnings 和稳定的 Channel 处理结果。

**Architecture:** 所有持久化内容先经过 Validate 和 Migration，再进入 Schema 校验、Serializer、Channel Adapter 和 Sanitizer。Import 只负责把受限标准 HTML 转为 Tiptap JSON，不承诺 Word、Google Docs 或任意 HTML 的无损转换。

**Tech Stack:** TypeScript, Tiptap 3, `@tiptap/html`, Zod, sanitize-html, Vitest, pnpm.

---

- [ ] **Step 1：定义当前 Schema 版本和迁移链**

版本使用稳定字符串，迁移边必须明确 `from` 和 `to`；不存在路径时返回 `MIGRATION_FAILED`，不猜测迁移方式。

- [ ] **Step 2：实现纯函数迁移执行器**

迁移器按有向链执行，不修改原文档；同一文档重复迁移到同一目标版本必须得到相同 JSON。

- [ ] **Step 3：实现迁移失败保护**

迁移失败时保留原始输入，不生成新的 HTML，不覆盖调用方的持久化数据。

## Task 2：实现标准 HTML Import

**Files:**

- Create: `packages/rich-text-server/src/import/html.ts`
- Create: `packages/rich-text-server/src/import/normalize.ts`
- Create: `packages/rich-text-server/src/import/index.ts`
- Create: `packages/rich-text-server/tests/html-import.test.ts`
- Modify: `packages/rich-text-server/src/index.ts`

- [ ] **Step 1：定义支持范围**

只接受标准 HTML 中的段落、标题、列表、链接、图片、blockquote、粗体、斜体和下划线；脚本、事件属性、表单、iframe、任意自定义标签和危险 URL 在解析前后均必须被拒绝或移除。

- [ ] **Step 2：实现 Pre-Sanitizer 和 Normalizer**

先清理危险标签和属性，再标准化空节点、无意义 span、标题级别、列表结构和基础 inline style。

- [ ] **Step 3：实现 HTML 到 JSON 转换**

输出必须是合法 `{ type: "doc" }`，并通过当前 Schema 校验；无法表达的结构返回可识别 warning 或 error。

- [ ] **Step 4：增加 Import 测试 fixture**

覆盖普通 HTML、空段落、嵌套列表、链接、图片、危险标签、危险 URL 和不支持标签。

- [ ] **Step 5：运行 Import 测试**

```bash

```

- [ ] **Step 6：提交标准 HTML Import**


## Task 3：统一 Server Pipeline 和 ProcessResult

**Files:**

- Create: `packages/rich-text-server/src/process.ts`
- Create: `packages/rich-text-server/src/result.ts`
- Modify: `packages/rich-text-server/src/channels/shopify.adapter.ts`
- Modify: `packages/rich-text-server/src/index.ts`
- Create: `packages/rich-text-server/tests/process.test.ts`
- Modify: `apps/demo/app/api/render-shopify/route.ts`

- [ ] **Step 1：定义 `ProcessResult`**

结果包含 `html`、`plainText`、`warnings`、`schemaVersion` 和 `channel`；失败使用结构化错误，不把底层异常作为稳定 API。

- [ ] **Step 2：实现处理顺序**

固定为：`validate envelope → migrate → schema validate → serialize → channel adapter → sanitize → result`。每一步都必须可单测。

- [ ] **Step 3：接入 Shopify HTML Channel**

保留 `renderShopifyHtml()` 兼容入口，同时推荐业务使用 `processRichText(document, { channel: "shopify-html" })`。

- [ ] **Step 4：处理 warnings 和不支持节点**

不支持节点只能产生显式 warning、降级结果或 error；禁止直接丢弃内容并返回看似成功的 HTML。

- [ ] **Step 5：更新 Demo API**

Demo 返回完整 `ProcessResult`，并展示 warnings；不引入数据库或真实 Shopify 发布调用。

- [ ] **Step 6：运行服务端和 Demo 验证**


- [ ] **Step 7：提交统一 Pipeline**

